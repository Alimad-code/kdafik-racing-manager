\# Formula UI Design System Skill

\## Goal

Create and preserve a visual system that feels like a modern Formula / FIA-inspired official motorsport digital product.

This project should feel like:

\- premium

\- sharp

\- controlled

\- technical

\- data-first

\- race-oriented

It should not feel like:

\- generic SaaS

\- playful mobile game

\- arcade neon racing game

\- card-heavy startup dashboard

\- casual sports app

\## Visual direction

Core reference qualities:

\- official race timing screens

\- standings dashboards

\- race control interfaces

\- motorsport broadcast graphics

\- premium dark UI with restrained accents

\- high information density with strong hierarchy

\## Design principles

1\. Data first

2\. Visual discipline

3\. Clear hierarchy

4\. Consistency across screens

5\. Minimal decorative noise

6\. Motorsport credibility

7\. Desktop-first clarity

\## Color system

Default direction:

\- dark base

\- high-contrast surfaces

\- restrained accent usage

\- semantic status colors

Recommended semantic layers:

\- background

\- elevated surface

\- table surface

\- border/subtle separators

\- primary text

\- secondary text

\- muted metadata

\- accent/action

\- success

\- warning

\- danger

\- info

\- stage statuses

Avoid:

\- rainbow palettes

\- excessive gradients

\- multiple competing accent colors

\- overly soft washed-out grayscale

\## Typography

Typography should feel:

\- precise

\- modern

\- broadcast-like

\- structured

Rules:

\- strong distinction between page title, section title, metric value, row label, metadata

\- standings numbers should be visually assertive

\- timing-related values should be easy to scan

\- table hierarchy should be stronger than card hierarchy

Prefer:

\- compact line heights where appropriate

\- high readability for tabular data

\- clear numeric emphasis

\## Layout and spacing

Layout should use:

\- rigid grid logic

\- consistent horizontal rhythm

\- dense but not cramped sections

\- page-level spacing that supports dashboard readability

Rules:

\- use spacious page framing

\- keep internal blocks disciplined

\- avoid large empty dead zones

\- avoid over-segmenting with too many card containers

\## Border radius and surfaces

Use restrained radius.

Do not make the product overly rounded.

Preferred feel:

\- technical

\- premium

\- sharp-edged or moderately rounded

Avoid:

\- bubbly component styling

\- soft toy-like cards

\- oversized shadows

\## Table system

Tables are one of the most important visual systems in this product.

All major result screens should feel like official motorsport timing or standings presentations.

Table rules:

\- high legibility

\- compact rows

\- clear numeric alignment

\- consistent status column behavior

\- clear driver/team info hierarchy

\- gap, interval, lap time, score, and position values should be scan-friendly

Create reusable patterns for:

\- standings table

\- qualifying grid table

\- practice timing table

\- race results table

\- championship standings table

\## Component families

Create and reuse these primitives:

\- PageHeader

\- SectionHeader

\- StatBlock

\- MetricRow

\- StatusBadge

\- InfoChip

\- TimingTable

\- StandingsTable

\- DriverSummary

\- TeamSummary

\- BudgetPanel

\- StageStatusPill

\- ActionPanel

\## Iconography

Use icons sparingly.

Icons should support scanning, not decorate everything.

Use icons for:

\- warnings

\- status

\- weather

\- team/car/track metadata if helpful

Do not overload primary data screens with decorative icon clutter.

\## Interaction style

Interactions should feel:

\- deliberate

\- precise

\- premium

Use:

\- subtle hover states

\- clear selection states

\- strong active states

\- restrained transitions

Avoid:

\- flashy motion

\- exaggerated transforms

\- playful micro-interactions

\## Screen patterns

Each screen should have:

\- clear page title

\- supporting metadata

\- primary action area

\- one dominant information block

\- supporting blocks beneath or beside it

Priority examples:

\- setup screens -> configuration first

\- practice results -> interpretation and timing first

\- qualifying results -> grid/times first

\- race results -> finishing order and gaps first

\- championship summary -> standings first

\## Empty/loading/error states

States must feel part of the same product.

Rules:

\- use the same typographic and spacing logic as main screens

\- do not fall back to generic skeleton chaos

\- keep status messaging concise and technical

\- preserve layout credibility even in mock/demo states

\## Anti-patterns to avoid

\- generic marketing gradients

\- giant rounded dashboard cards everywhere

\- too much whitespace

\- overuse of glassmorphism

\- loud neon racer aesthetics

\- mobile-first compression applied blindly to desktop

\- excessive decorative illustration

\## Definition of done

Design system work is done when:

\- the interface feels recognizably motorsport-inspired

\- screen patterns are consistent

\- tables look intentional and premium

\- typography supports data-heavy scanning

\- the product no longer looks generic
